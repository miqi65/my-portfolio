03/ Problem Solving

我解决什么问题

从模糊需求到清晰方案，从旧流程到更可控的协作流程，从静态界面到可验证原型，从开发前到风险识别。

01

Ambiguous Requirements -> Clear Solution

模糊需求 -> 清晰方案

把老板和客户的抽象想法拆成角色、流程、任务和边界，让团队先知道要解决什么。

02

Legacy Flow -> Clearer Collaboration Workflow

旧流程 -> 更清晰的协作流程

识别每一步并结合自动化辅助，明确协作边界与交付标准，让流程更稳定、责任更清晰。

03

Static UI -> Testable Prototype

静态 UI -> 可验证原型

用原型帮助团队提前识别方案是否值得推进，而不是等开发后才发现问题。

04

Before Development -> Risk Checklist

开发前 -> 风险清单

提前暴露权限、数据、算法、硬件和上线风险，减少后期返工。

05/ Method

我的工作方式

以系统思维和用户价值为核心，通过结构化方法与高效协作，把复杂产品从模糊想法推进到可验证、可评估、可落地的方案。

拆业务

理解业务目标、客户场景、用户任务和现实限制，先把问题讲清楚。

做判断

判断哪些功能值得做，哪些需要优化，哪些边界必须保留人工确认。

做原型

用交互原型验证方案方向，而不是等开发后才发现问题。

控风险

提前暴露权限、数据、算法、硬件、成本和上线风险。
